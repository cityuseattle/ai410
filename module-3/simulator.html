What this teaches

  • Nondeterminism means "usually right" isn't "right." Send 20 with the guardrail off: some fraction crash, and you can't predict which.
  • Retrying blindly helps less than you'd think. Turn off "feed the error back" — the model repeats the same mistake. The Analyze stage asks why the error goes into the next attempt.
  • Failing to {"error": …} is a success. It keeps the request alive so the model can explain, like HOS 1's try/except.
  • Inline ingestion blocks everyone. In inline mode, "hi" waits behind the whole document. With a queue, the upload returns a job_id instantly.
  • A queue with no worker is a silent bug. Set workers to 0: uploads "succeed" and jobs stay queued forever. It's the #1 HOS 3 snag — the worker runs in its own terminal.
