GitHub

First needed: HOS 1Free — no credit card

What it's for: hosting your own copy of each HOS's starter code, and — the recommended path all term — GitHub Codespaces, a ready-made cloud dev environment that sidesteps the most common setup bug in this course (an old package on your own machine silently shadowing the project's real one).

  1. Go to github.com and click Sign up (top right).
  2. Enter an email, create a password, and pick a username. Use something professional — this account is worth keeping and using beyond this course, for internships and job applications.
  3. Verify your email when GitHub sends the confirmation.
  4. That's it for a free account — no payment information is requested or required.
Already have a GitHub account from a bootcamp, another course, or personal projects? Use that one — don't create a second account. One consistent GitHub profile is more useful to you later than several scattered ones.

You'll know it worked when…

  • You can sign in at github.com, and can see the option Code → Codespaces → Create codespace on main on any repository (including your own copy of a starter-code folder).

Google AI Studio: Gemini API key

First needed: HOS 1Free — no credit card

What it's for: the API key that lets your backend talk to Gemini. You get this once, in HOS 1, and reuse the exact same key for every remaining HOS — chat, embeddings, everything.

  1. Go to aistudio.google.com/apikey and sign in with any Google account (a personal Gmail account is fine — you don't need a special one).
  2. Click Create API key.
  3. Copy the long string it gives you — it starts with something like AIza....
  4. Paste it into your project's .env file: 
    GEMINI_API_KEY=AIzaSyD-your-real-key-goes-right-here
Treat this like a password. Anyone who has your key can make Gemini requests billed to your account. Never paste it into a file you commit to Git, a chat message, or a screenshot — that's exactly why it lives in .env and not in your code.

You'll know it worked when…

  • You have a copied key starting with AIza saved in your own notes somewhere safe, and pasted into .env as GEMINI_API_KEY (not .env.example — that file is just a template).

Upstash: Redis database

First needed: HOS 3Free — no credit card

What it's for: Redis is the fast, simple database your background job queue runs on — one process (your API) adds "please ingest this document" tasks to it, and a separate worker process pulls them off. Upstash gives you a managed, free Redis instance with no server to install yourself.

  1. Go to upstash.com and sign up — GitHub or Google sign-in both work, so you likely don't need a new password.
  2. Click Create database.
  3. Choose the Redis type, give it any name (e.g. ai410-queue), and pick a region close to you. Leave other settings at their defaults.
  4. Once it's created, open the database's page and find the connection string / URL field — not just the hostname. Click to copy the whole string.
  5. Paste it into backend/.env as REDIS_URL, alongside your existing GEMINI_API_KEY.

What that connection string actually means

It looks intimidating, but it's five plain pieces glued together in one line — the same shape as any URL, just with a login baked in:

rediss://default:AbCdEf123...@your-instance-name.upstash.io:6379
Scheme Username Password Host Port
Piece by piece
rediss://
the protocol — this is TCP under the hood (Redis's own wire protocol, not HTTP), and the extra s means the connection is TLS-encrypted. Upstash requires this — don't swap it for plain redis://.
default
the username. Upstash's free tier always uses the literal username default — you didn't choose it and don't need to change it.
AbCdEf123...
the password, auto-generated by Upstash specifically for this database.
your-instance-name.upstash.io
the host — the actual address of your Redis database on the internet.
6379
the port — Redis's standard port, on every provider, essentially always this number.
Why copy the whole string instead of the pieces separately? The library this course uses (Redis.from_url(...)) reads all five pieces out of one string at once. Copying just the hostname, or just the password, means your code has no way to authenticate or find the right port — you need the entire rediss://... line, exactly as Upstash shows it, pasted as one value.

Common snags

  • Copied only the hostname — if REDIS_URL in your .env doesn't start with rediss://, you copied the wrong field. Go back to the Upstash dashboard and look for a field explicitly labeled "connection string" or "URL," not "endpoint" or "host" alone.
  • Used redis:// instead of rediss:// — Upstash's free tier requires the TLS-secured version. If Upstash's dashboard shows you both, always use the one with the extra s.
  • Pasted it with surrounding quotes — a .env value shouldn't have quote marks around it: REDIS_URL=rediss://..., not REDIS_URL="rediss://...".

You'll know it worked when…

  • Your .env has one line starting REDIS_URL=rediss://default:...@...upstash.io:6379, and HOS 3's queue_setup.py can connect without a connection error.

Expo: account, login & EAS project ID

First needed: HOS 4Free — no credit card

What it's for: two separate things, both solved by the same free account. First — on current versions of Expo Go for iOS, you must be logged in to the same Expo account in both your terminal and the Expo Go app just to load the project at all (a newer Expo Go requirement, not specific to this course). Second — requesting a push token specifically also requires the app to be linked to a project on Expo's own servers (EAS), separately from the login above.

  1. Go to expo.dev/signup and create a free account.
  2. Log in on the CLI — in your Codespaces terminal, inside mobile/: 
    npx expo login
    It prints a link; open it, sign in with the account from step 1, and the terminal picks it up automatically.
  3. Log in on your phone too — open the Expo Go app, tap the avatar/profile icon in the top-right of its home screen, and sign in with the same account. Both have to match — logged in as one user in the terminal and a different one (or no one) in Expo Go won't load the project.
  4. Then, for push notifications specifically, still inside mobile/: 
    npx eas init
    It'll confirm you're logged in (from step 2) and confirm creating a new project — say yes. It writes an extra.eas.projectId field directly into your mobile/app.json for you; you don't edit anything by hand.
  5. Restart npx expo start --tunnel so the app picks up the updated login state and app.json.
Chat still works without the EAS project step (step 4). Only "register for push notifications" needs it — the guides' starter/answer code already fails on that one step gracefully (a console warning, not a crash) if you haven't done it yet. But steps 2 and 3 (logging in on both ends) currently gate everything in Expo Go on iOS, chat included. This is rolling out to Android too, just not required there yet.

Don't want to deal with phone login or Expo Go at all? Use Expo web instead

For quickly testing the chat screen — no phone, no Expo Go, no account login required — run this inside mobile/ instead:

npx expo start --web

This opens the app in a regular browser tab (in Codespaces, it uses the forwarded-port preview automatically). It's the fastest way to confirm the chat UI and your backend connection work before dealing with phones at all. Trade-off: push notifications don't exist on Expo web — expo-notifications isn't supported there, so Device.isDevice is false and this app's code already skips push registration cleanly on its own (no error, it just doesn't run). Use web to verify chat, then switch to a real phone only for the push-notification stages.

"Project is incompatible with this version of Expo Go"

The Expo Go app on your phone only ever supports the current Expo SDK — and it auto-updates itself, so which SDK counts as "current" keeps moving forward over time, independent of this course. If the version this project is pinned to falls behind, Expo Go will refuse to open it and tell you exactly which SDK it wants instead. Fix it by upgrading the project to match, right inside mobile/:

npx expo install expo@latest
npx expo install --fix

The second command re-aligns every other Expo/React Native package to versions compatible with whatever expo@latest turned out to be. Restart npx expo start --tunnel afterward. This will happen again the next time Expo ships a new SDK — the fix is always these same two commands.

You'll know it worked when…

  • The project actually loads in Expo Go on your phone (not stuck on a login/loading screen) — confirming the CLI and phone are logged into the same account.
  • mobile/app.json has a new extra.eas.projectId field after running eas init, and the app logs a real push token to the console instead of the "No EAS project ID found" warning.

Langfuse

First needed: HOS 4Free — no credit card

What it's for: observability — recording what actually happened on every real request (timing, inputs, outputs, cost) so you can look at data instead of guessing when something's slow or wrong. You won't need this until the observability HOS, but it's included here so this page covers every account the course asks for.

  1. Go to cloud.langfuse.com and sign up.
  2. Create a new project (any name — e.g. ai410).
  3. Go to Settings → API Keys and create a new key pair. You'll get a Public Key (starts with pk-lf-...) and a Secret Key (starts with sk-lf-...).
  4. Add all three to backend/.env: 
    LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com
Two keys, not one. Unlike the Gemini key, Langfuse gives you a pair — a public key and a secret key — both required together. If either is missing, tracing calls will fail silently or error at startup depending on the SDK version, so double-check both made it into .env.

You'll know it worked when…

  • Your Langfuse project's Traces tab shows real entries after you send a few chat messages through your HOS 4 app.
🧩

Putting it all together

By the end of the term, your backend/.env holds all four — but you add them one at a time, as each HOS needs them, not all on day one:

# HOS 1
GEMINI_API_KEY=AIzaSyD-your-real-key-goes-right-here

# HOS 3
REDIS_URL=rediss://default:AbCdEf123...@your-instance-name.upstash.io:6379

# HOS 4
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com

This file is already excluded from Git by this project's .gitignore — it stays on your machine (or your Codespace) only, never committed.
