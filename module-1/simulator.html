    What this teaches

    • The model only asks; your code runs. Every tool call passes through the Backend lane — Gemini never touches the Python function.
    • The loop can repeat. Try the two-part question with both tools on: two function calls, then text. Drop max iterations to 1 and watch the backend cut it off.
    • A missing tool doesn't cause an error — it causes a guess. Turn calculate off and ask the math question. The answer looks confident and is wrong. That's what Evaluate is for.
    • Failures should be data, not crashes. Turn off try/except and send the broken expression.
    For your Team Project List the 2–4 tools your project's agent needs. For each, write the one-line description the model would read — then ask: would a vague description make the model call it at the wrong time? Pair with the Application Challenge's auto / confirm / never sort.
