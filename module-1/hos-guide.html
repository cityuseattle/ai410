HOS 1: Foundations & the Agentic Loop

Build a full-stack chat app that can call a real tool — using an AI coding assistant to scaffold it fast, then proving, in writing and by hand, that you actually understand what it built.

Est. 2–2.5 hrsOutcome 1Module 1 · Weeks 1–210% of final grade
Before you start Create Evaluate Analyze Understand & Refine Common snags
🧭

Before you start

  1. Check your account setup. This module needs a GitHub account and free Gemini API key. Set it up first; the build won't run without it.
  2. Know the concepts. Read Concept Companion → Module 1 before you open the starter code.

What you'll need

  • Starter code: your HOS 1 repo, created when you accept the HOS 1 invite — deliberately close to empty; see its README for why. Not sure what a file does? See the starter code walkthrough for this HOS.
  • Python 3.11+ and a terminal (or GitHub Codespaces — recommended, see the folder's .devcontainer)
  • An AI coding assistant available in your environment — GitHub Copilot Chat (built into Codespaces, use Agent mode), Claude Code, or equivalent
  • A free Gemini API key (no credit card required) from aistudio.google.com/apikey

This HOS is graded across four stages instead of on code correctness alone: Engagement (Create/Scaffold) is 20% of the HOS grade, and Skills is 80%: Evaluate, Analyze, Apply (the change you make by hand in Understand & Refine) and Understand (your own explanation of it), 20% each. Each stage below says exactly what to submit. Everything goes in your Module 1 GitHub Classroom repo: written work under the matching heading in NOTES.md, screenshots in screenshots/. Commit and push as you go, then submit the repo link to the HOS 1 assignment in Brightspace by the end of Week 2.

🛠️

1 · Create / Scaffold

Graded as Engagement: 20% of this HOS. The AI-assisted starting point, not the deliverable.

Open your starter-code folder in Codespaces (or locally) and prompt your AI assistant to build the app. A reasonable starting prompt:

Build a full-stack chat app in THIS existing workspace (the starter-code
folder that's already open) — edit files here; do not create a new
workspace or project:
- backend/: a FastAPI server with a POST /chat endpoint that calls the
  Gemini API (google-genai) with model "gemini-3.8-flash" (kept in one
  MODEL constant), reading GEMINI_API_KEY from backend/.env.
  Give it an agentic loop: the model should be able to call a real
  tool (e.g. a calculator) via function calling, and the tool's result
  should go back to the model before it replies.
- frontend/: a Streamlit chat app that calls the backend's /chat
  endpoint over HTTP.
- requirements.txt files for both.

Two things the prompt pins down on purpose (both caught in testing — see Common snags): where the files go, and which Gemini model to call. Keep both lines if you rewrite the prompt.

Sample run: Stage 1 in a faculty test Codespace (GitHub Copilot Chat, Agent mode)

One run, start to finish, so you know what to expect. Your assistant will produce different code. Click a screenshot to open it full size.

Iterate with it until you have a working chat app that can call at least one tool. Don't hand-edit anything yet — this stage is entirely AI-driven.

Submit (Engagement)
  • The prompt you gave your AI assistant, and a screenshot of the scaffolded app running.
🔍

2 · Evaluate

The critical gate — is the AI-produced result actually correct?

Test it on purpose. At minimum, try:

  • A message that clearly needs the tool (e.g. "what's 342 times 87?") — did it actually call the tool, or guess the answer in text?
  • A message that doesn't need the tool at all — did it answer directly instead of forcing a tool call?
  • An input that could break the tool (e.g. an incomplete expression) — does it fail gracefully, or crash the whole request?
Submit
  • A short written note: what you tested, what you found, and anything the AI got wrong, missed, or handled surprisingly well.
🔬

3 · Analyze

Why does this work, mechanically?

Pick one specific piece of the AI-generated backend code — most naturally, the part of the agentic loop that decides whether the model wants to call a tool — and explain, in your own words, exactly how it works. Don't summarize the whole file; go deep on one mechanism.

Submit
  • A short written walkthrough of the one piece you chose, in your own words.
✋

4 · Understand & Refine

The mastery check — can you extend it correctly, without AI doing this part too?

By hand this time — no AI assistance for this stage.

Add a second tool to the agent yourself — something different from whatever your AI assistant built in Stage 1 (a word counter, a unit converter, a date lookup — anything with a clear, testable behavior). Register it correctly alongside the first tool, and confirm the agent calls the right tool for the right question.

Submit
  • A screenshot of the working app, showing both tools firing correctly on different messages.
  • The code for the tool you wrote by hand.
🧯

Common snags

  • Copilot Chat builds the app somewhere other than your starter folder — in Codespaces, the default Copilot Chat agent tends to scaffold a brand-new workspace/folder of its own (and may offer to open it) instead of editing the starter-code workspace that's already open — so your .devcontainer and backend/.env.example get left behind. Use Agent mode with the starter folder open, and say explicitly “in this existing workspace, don't create a new one” (the starter prompt above does). If it already happened, delete the stray folder and re-prompt; don't try to merge the two.
  • 502 Bad Gateway (or a 404 / “model not found”) from /chat — almost always the model name. AI assistants default to whatever model was current in their training data — e.g. gemini-2.5-flash, which is no longer available to new API keys. The backend's Gemini call fails, and the frontend reports it as a 502. Set the model to gemini-3.8-flash (tested working in Codespaces with a fresh free key), restart uvicorn, and try again. If that ever stops working too, check the current list at ai.google.dev/gemini-api/docs/models and use the current Flash model — this is exactly why the model name belongs in one constant.
  • The AI assistant adds CORS middleware — you don't need it. The Streamlit frontend calls the backend server-side (Python to Python), not from JavaScript in a browser, so CORS is irrelevant here. Fine to remove if you notice it.
  • The agent always calls the tool, even when it shouldn't — check the tool's description in its schema. A vague description ("does math") makes the model over-eager; a specific one narrows it down.
  • Two terminals, easy to forget — the backend (uvicorn) and frontend (streamlit run) are separate processes. If the frontend can't reach the backend, check both are actually running.

Most snags trace back to a concept. If one doesn't make sense, see Concept Companion → Module 1.
